# 검증 명세

## 실행 계약

Django는 `RunInput`에 맞는 설정을 전달한다. `execute_run(config, policy_factory, output_dir, emit_event, should_cancel)`은 세션별 결과와 이벤트를 생성한다. 현재 공개 형식의 기준은 [schemas.py](../agent/schemas.py), 실행의 기준은 [runtime.py](../agent/runtime.py)다.

현재 GUI는 통제된 웹 브라우저다. 행동은 현재 `Action` 스키마와 `act` 실행기가 함께 지원하는 종류만 허용한다. 지원 행동은 click·fill·scroll·stop·hover·select·check/uncheck·press·wait·back/forward·reload다. 스크린샷은 각 관찰에서 자동 수집하며 별도 모델 행동으로 노출하지 않는다. select의 허용 option·press의 허용 키·wait의 시간 범위를 실행기가 검증하며, 행동 범위의 증거는 ACTION-01·ACTION-02 테스트로 남긴다. 임의 JavaScript·shell 실행을 모델 도구로 노출하지 않는다. iframe·새 탭 제어는 미지원이다. 데스크톱 전체·실결제·실인증·임의 고객 URL의 공개 실행은 범위 밖이다. origin 제한은 SSRF 방화벽을 대체하지 않는다.

## 증거와 판정

브라우저 gate는 pytest JUnit 결과에서 요구 테스트가 모두 실행됐는지 확인한다. 실패는 fail, 필수 테스트 누락·skip·의존성 없음은 blocked다. live gate는 `openai` 정책·실제 호출 시도·정상 과업 완료가 결과에 남았는지 확인한다. 단순 반환 텍스트나 exit code 하나만으로 성공 처리하지 않는다.

쇼핑몰 조건은 `--shop normal/problem/fixed`, 문제 분리는 `--case all/signup/fee/cta`로 실행한다. SHOP-01의 고정 정책은 모델 판단 성능이 아니라 프론트와 실행 루프 연결의 증거다. SHOP-02는 배송비·CTA의 UI 조건 검사이며 자동 원인 분류 정확도를 뜻하지 않는다.

각 판정에는 실행 시각, 명령 argv, Python 경로, 소스 SHA-256, 로그 경로를 남긴다. browser pass는 MODEL-LIVE-01을 충족하지 않는다. SDK mock은 실제 API 응답·모델 권한의 증거가 아니다. model 프로필은 아직 `--demo normal`의 단순 통제 과업이며, 실제 반찬로드 프론트에서 모델이 전체 주문을 수행하는 E2E 검증은 별도 미검증이다.

## 미구현·별도 검증

일반 웹사이트 진단 정확도, 실제 고객 이탈률, 숨은 배송비·시각적 CTA의 자동 분류, 배포 간 동일 이슈 대응·해결 확인·알림 오탐률은 위 gate의 통과만으로 검증되지 않는다. 새 기능이 생기면 요구사항 ID와 실제 평가 데이터를 함께 추가한다. 단순 페이지 복잡성 증가는 검증 성능의 증거가 아니다.

| ALIGN-03 | 그래프 단계 선택·계산 내역·사람 입력 폼 보존·API 저장·근거 경로 비노출 | 실제 로컬 브라우저 |

좌절 모델 v1은 `max(0, .85 F + 16 신규 필수입력 + 8 단계재방문 - 4 신규단계진전)`이며 임계치는 입력 허용치 ×16이다. 파라미터는 초기 가설이며 실사용자 데이터로 보정되지 않았다. 확률 추첨 없이 임계치 초과 시 중단한다. 실행기/스크린샷 지연은 사용자 대기 신호로 가산하지 않는다. v1은 입력·단계 재방문·진전만 측정했다. 현재는 아래 v2의 탐색·늦은 배송비 신호도 적용한다.

Human Alignment는 같은 실행의 같은 버전/과업/기기 조건을 사람이 확인해 수동 대응시킨 관측이다. 실제 여부는 독립 검증하지 않으며 합성 데이터를 실제 관측으로 자동 생성하지 않는다. 결과 지표는 비교 가능한 성공/가상 이탈 세션 전체, 단계 지표는 그중 사람 중단 건, 원인 지표는 그중 원인이 알려진 사람 중단 건을 분모로 사용한다. 기술 실패 등은 제외 건수로 표시한다. 같은 익명 참여자는 과업당 1건만 집계하며 수정 입력은 대체한다. 종합 신뢰도나 실제 고객 이탈 확률을 산출하지 않는다.

| TASK-02 | 4과업×3프로필에 서로 다른 12세션 할당, 미지원 과업 거부 | 실행 계약 |
| TASK-03 | 탐색 비용에 프로필 가중치 적용, 늦은 배송비 노출 중복 가산 방지 | 모형 신호 |

과업은 첫 주문·배송 지역 확인·쿠폰으로 주문·다음 배송 건너뛰기다. 모두 합성 세션 저장소만 변경하며 실제 구독/계정/배송을 변경하지 않는다. 과업 성공은 각 경로 및 쿠폰 적용 표식을 확인한다. 전체 과업 선택 시 12세션을 대기열에서 최대 3개씩 실행한다. 각 과업/프로필마다 새 provider 브라우저를 만들며 상태를 공유하지 않는다.

좌절 모형 v2는 v1에 `10×탐색민감도×탐색스크롤` 및 `40×비용민감도×늦은배송비노출`을 추가한다. 탐색 스크롤은 직전 실제 scroll 동작이 같은 단계에서 수행된 경우 관측한다. 늦은 배송비는 현재 데모의 보이는 경고 문구로만 판별하고 세션당 한 번 가산한다. 범용 비용 충격 탐지기로 주장하지 않는다. 가중치는 실사용자 보정 전의 초기 가설이다.

Human Alignment는 과업을 포함한 세션 ID에 대응한다. 같은 익명 참여자는 과업별 1건만 저장하며, 여러 과업의 관측을 독립 사람 표본으로 해석하지 않는다.

완료된 페르소나 실행은 `/api/personas/report?run_id=...`와 `.md` API에서 정해진 규칙으로 리포트를 만든다. 보고서에는 과업 결과, 위치별 가상 이탈 건수, 문제 시점의 단계/경로/필수 입력/탐색/비용 신호, 직전 행동, 좌절 점수와 임계치, 당시 캡처, 개선 가설이 들어간다. 문제 시점 캡처가 없으면 최종 화면으로 대체하지 않고 누락으로 표시한다. 기술 실패/한도/인증 차단을 UX 이탈로 집계하지 않는다. 저장된 완료 실행은 다음 실행 중에도 실행 ID로 조회한다. 요약 저장은 임시 파일 후 교체하여 읽는 중 불완전 JSON 노출을 줄인다.

리포트의 영향 분모는 같은 과업의 전체 가상 세션(기술 실패 포함)이며 실제 사람 전환율이 아니다. 검토 순서는 관측된 영향 세션 수 기준이다. 개선안은 원인/단계에 따른 고정 가설이며 실제 개선 효과를 검증한 결과가 아니다.

## 문제 영역 표시와 개선 목업

| ID | 계약 | 검증 |
|---|---|---|
| VISUAL-01 | 보이는 요소 DOM bbox·뷰포트 좌표·CSS 픽셀 캡처 정렬·숨은 요소 제외 | DPR 2 실제 브라우저 |

관측에서 보이는 필수 입력과 늦은 배송비 문구의 DOM 좌표를 저장한다. 캡처는 CSS 픽셀로 저장하여 기기 배율과 상관없이 좌표계를 맞춘다. 리포트는 해당 좌표를 SVG 박스로 덧그리며 문제 영역 중심으로 확대한다. OCR을 실행하거나 과거 캡처에서 좌표를 추정하지 않는다. 좌표가 없는 과거 실행/화면 밖 탐색 대상은 박스 없이 미확보 사유를 표시한다. 확대 뷰어는 원본 전체 화면과 박스를 함께 보여주고 화면 맞춤/100%/200%를 제공한다.

가입 문제에는 기본 image_gen으로 실제 캡처를 참조해 생성한 개선 가설 이미지 1장을 제공한다. 원본 자산은 `saas-web/assets/mockups/signup-guest-v1.png`, 프롬프트/출처는 같은 폴더 README에 기록한다. 실제 수정·재검증 화면과 구분하여 AI 생성/적용 전/효과 미검증으로 표시한다. 문제마다 자동 생성하는 기능은 아직 없다.

| SETUP-02 | 확인된 기능·과업·연령 입력 검증, 연령으로 행동 가중치를 임의 변경하지 않음 | 계획/세션 할당 |
| SETUP-03 | 기능 확인→과업 추가/제외→타겟 질문, 최종 확인 전 실행 없음 | 실제 UI |
| EXPLAIN-01 | 기록 근거 답변·모르는 이유 구분·세션 저장·오래된 실행 거부 | 저장/설명 규칙 |
| EXPLAIN-02 | 카드 팝업·종료 캡처·질문 응답 추가·Escape 복귀 | 실제 UI |

기능 탐색은 현재 로컬 반찬로드에 한정한다. 추가 요청 자유 입력은 검토 메모이며 자동 실행 과업으로 변환하지 않는다. 연령은 타겟 문맥이며 실사용자 보정 전 행동 예산에는 반영하지 않는다. 질문 답변은 기록 기반 규칙이며 모델 호출은 0회다. 기록되지 않은 심리나 실제 사람 전환율을 추정하지 않는다. 특정 행동의 설명은 기록된 동작·과업·고정 정책 범위에서만 제공한다.

세션 팝업은 최대 1160px, 화면 높이의 84%(최대 760px)로 제한하며 데스크톱 설명 영역을 약 40%로 확보한다. 종료 세션은 카드 개방 시 종료 이유 질문을 자동으로 요청·저장하여 펼쳐 보여준다. 같은 질문이 저장된 경우 재요청하지 않는다. 설명 본문은 15px 이상으로 표시한다. 실행 중에는 종료 이유를 미리 생성하지 않는다.

PDF는 기존 리포트 화면과 같은 JSON을 사용하고 상세 세션을 펼쳐 인쇄한다. 서버는 loopback의 GET과 로컬 자산만 허용하며 외부 URL을 입력받지 않는다. 로컬 동시 생성은 1건이고 운영용 비동기 생성·객체 스토리지·권한·캐시는 미구현이다. 생성 실패는 503으로 표시하며 불완전 파일을 성공으로 반환하지 않는다.
