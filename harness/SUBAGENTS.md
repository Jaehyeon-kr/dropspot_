# 서브에이전트 작업 경계

이 문서는 역할 템플릿이다. 저장소를 읽었다는 이유로 자동으로 여러 에이전트를 실행하지 않는다. 사용자가 병렬 작업을 요청했거나 해당 작업에 명시적 위임이 있을 때 활용한다.

| 역할 | 입력 | 수정 범위 | 인계 산출물 |
|---|---|---|---|
| 구현 | SPEC ID·기존 인터페이스·목표 동작 | 할당받은 런타임 또는 프론트 파일 | 변경 파일·호환성·자체 확인 |
| 검증 | 실제 사용자 과업·테스트 웹·검증 스킬 | 별도 평가 산출물, 합의된 테스트 파일 | verdict·실패 재현·근거 위치 |
| 리뷰 | diff·명세·검증 결과 | 기본 읽기 전용 | 결함·근거·남은 위험 |

검증 담당에게 정답을 행동 모델 프롬프트에 넣으라고 지시하지 않는다. 사람 평가용 정답표와 에이전트가 관찰할 화면을 분리한다. 독립 검증이 목적이면 구현자가 기대하는 결론보다 과업·관찰·수용 기준을 전달한다.

요청 예시:

```text
SPEC의 EXEC-01과 EXEC-03을 현재 테스트 웹에서 검증하세요.
.agents/skills/dropspot-verify/SKILL.md를 읽고 browser gate를 실행하세요.
런타임 파일은 수정하지 말고, verdict 경로와 재현 가능한 실패·미검증 항목을 보고하세요.
```

최종 통합 담당은 각자의 결과를 그대로 합격으로 합치지 않는다. 파일 충돌·소스 변경 여부를 확인하고 통합된 소스에서 필요한 gate를 실행한다. 같은 작업 중 소스가 변경돼 fingerprint가 바뀌면 이전 검증은 현재 소스 통과 증거로 쓰지 않는다.
