## 4. 개발 묶음과 의존성

1. **계약/기반:** PO-01/02/03 + AG-01 + BE-01/02/18, FE는 mock 기반으로 공통 레이아웃과 상태를 병행.
2. **URL 수직 흐름:** 대상 준비→탐색→확인→실행→근거→리포트. BE-03~15 + FE-02~14 + AG-02~05. 하나의 실제 외부 테스트 환경에서 검증.
3. **운영 준비:** 취소/장애/권한/삭제/비용·성능을 포함해 P0 수용 시험. ‘정상 데모만 됨’을 출시 완료로 처리하지 않음.
4. **코드 보강:** source 읽기/버전 대응 먼저, preview build는 격리 준비 후. URL-only에 회귀가 없어야 함.
5. **반복 관리:** 비교·예약·알림·사람 검증. 데이터가 있어야 평가 가능한 정확도는 구현 완료와 검증 완료를 분리.

각 티켓은 API/화면·오류 상태·권한·관측 로그·관련 S/PERF 수용 시험까지 완료해야 닫는다. 티켓 개수는 공수나 사람별 기여 비율이 아니다. 추정은 대상 사이트/인증 방식/공급자/릴리스 범위 결정 후 한다.
